# Standing production directive — Shire Journey 3D
Adopted on explicit owner request 2026-10-17. Applies to The Shire and every subsequent chapter.

**Solve blockers; do not settle for excuses or vague status updates.**
- Prefer verified implementation, playable improvement and evidence over plans, summaries and claims.
- When a blocker appears, inspect source, logs, primary Godot documentation and relevant developer/community discussions. Implement the best licensed, maintainable solution and retest.
- Keep all production outputs, fixes, asset provenance and QA results in the repository with precise commit/CI links.
- Never call a chapter *finished*, *photorealistic* or *cinematic-final* just because a Windows executable launches; check actual in-engine imagery, scene coverage, interaction and performance.
- Prioritize character/environment fidelity, convincingly inhabited villages, believable animation, sound, narrative, save/load and user-visible flaws.
- Retain a working build candidate before significant changes; avoid destructive shortcuts or stolen film/game models.
- Keep a realistic distinction between features actually implemented/tested and art/voice/hardware QA that cannot yet be verified.
- Continue meaningful work within the currently active authorized working session. Do not promise unattended/background execution without a separate scheduled automation.
- Apply one high-quality bar across The Shire and the entire game.

**Definition of current priority**: eliminate observed camera/scene defects and avoid excessive per-object draw calls in busy scenes; build test coverage that *fails* if a prominent scene is a flat obstruction. Then address highest-visibility asset deficits with traceable rights and real renders.
